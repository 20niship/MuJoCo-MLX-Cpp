Why this library

Keep your MuJoCo models and workflow. Get GPU throughput without a vendor lock-in.

Faster than Isaac Lab and Genesis

Go2 env.step on an RTX 3060: 3.4× Isaac Lab and 1.6× Genesis at 4096 envs (409K vs 120K / 252K env-steps/s), 1.7× Genesis at 16384 envs, 1.3× at 1024 — and ahead of Isaac Lab at every measured size. With a camera on every env: 4.1× Genesis, up to 2.7× Isaac Lab TiledCamera. Caveats are listed under the charts.

Same models as MuJoCo

Reads the same MJCF XML through MuJoCo's own parser — menagerie Go2 / G1 / Piper, Gymnasium Humanoid / HalfCheetah, your own. No conversion, no new asset format. CI checks the GPU engine against MuJoCo C trajectory by trajectory.

No NVIDIA GPU required

Physics and rendering are Vulkan compute / graphics only. NVIDIA, AMD, Intel, or plain CPU through Mesa lavapipe (what CI uses). Only the zero-copy camera→PyTorch path needs NVIDIA + CUDA; otherwise you read images back through the CPU.

Cross-platform by design

Linux is tested (NVIDIA + lavapipe). The Vulkan layer also targets macOS via MoltenVK, but macOS is not yet verified for this repo — we say so rather than guess.

Almost no dependencies

libmjmlx links only libvulkan and libmujoco. Build needs the Vulkan headers, glslangValidator (shaders are compiled on first use), CMake and a C++20 compiler. No CUDA toolkit, no ML framework, no Python for the C/C++ libraries.

One API, CPU or GPU

libmjb exposes a single C API with a backend enum: MuJoCo C (float64, thread pool) or the GPU engine. Same code, easy A/B against the reference.

Built for RL

Observation / reward on the training device, packed single-transfer read-back, batched cameras, load-time contact simplification for speed. Isaac Lab–style Go2 environment included.

What it is

A MuJoCo-compatible physics pipeline reimplemented as GPU compute, checked against MuJoCo C, built for reinforcement learning at scale.

MuJoCo-faithful

Pyramidal friction (condim 3/4/6), plane/box/cylinder/ellipsoid/mesh/SDF contacts, joint limits, friction loss, fixed + spatial tendons, sensors. GPU trajectories are compared against MuJoCo C in CI.

Fast where it counts

One hand-tuned solver kernel per env in shared memory, fused kinematics and Euler, GPU-side observation packing. No per-step CPU round trips.

Cameras in the loop

Every env × every camera in one indirect draw. RGB + depth land directly in CUDA tensors via Vulkan→CUDA interop. Zero CPU copy.

Drop-in for RL

Go2 environment, rsl_rl PPO training, Isaac Lab–style rewards. Also a C API (mjb.h) for Unity/C# and anything with FFI.

Physics throughput

Faster than both Isaac Lab and Genesis at 1024 envs and above (about on par with Genesis at 256). Unitree Go2, flat ground, dt 0.005 × 4 substeps, random actions. Same hardware class, observations and rewards included.

How it works

A three-stage GPU pipeline per substep, no host synchronisation inside the loop.

qpos→Kinematics kernel→Forward / CRB / RNE→Collision (baked pair table)→Newton solver
1 workgroup per env, shared memory→Euler (direct from solver qacc)→GPU pack → torch

Backends

Vulkan compute through the mlx_vulkan (MKX) submodule. Tested on NVIDIA; CI runs on lavapipe (software Vulkan). The Metal backend was removed.

Solver

Newton with a shared-memory Cholesky direction, early exit on cost decrease, ~72 constraint rows/env. About 60–75% of GPU time.

Camera

Indirect draw of all (env, camera, geom); compute culling + vertex-clustered LOD; pack pass into (env, cam, H, W).

Verified

CPU/GPU trajectory tests, per-feature MuJoCo conformance, robustness sweeps over nv × constraint types. Details in ARCHITECTURE.md.

Usage

From a model file to training, cameras, and the C API.

1 · Load an MJCF and step thousands of envs

import sys; sys.path.insert(0, "build")
import _mjmlx_rl_native as native

model = native.load_model("unitree_go2/scene.xml")         # same MJCF MuJoCo reads
sim = native.create_batched(model, 4096, frame_skip=1)      # 4096 envs on the GPU (use_gpu=True is the default)
sim.step(ctrl, 4)                                           # ctrl: (4096, nu) float32; 4 substeps per call
qpos, qvel = sim.state()                                    # numpy (4096, nq) / (4096, nv)

2 · Speed knobs at load time (default is exact MuJoCo behaviour)

model = native.load_model(path, self_collision=False, max_condim=3)   # +15-23% env-steps/s

self_collision=False drops robot-vs-robot contacts; max_condim=3 removes torsional/rolling foot friction. The MJCF file is never modified; terrain is untouched. Pass the same options to the CPU reference when comparing.

3 · Train Go2 with rsl_rl PPO

uv sync --group build --group go2
uv run python scripts/examples/go2/train_go2_ppo.py --build-dir build --flat --reward-preset isaac_flat \
    --device cuda --envs 4096 --max-iterations 1500 --logdir runs/go2_flat
uv run python scripts/examples/go2/play_go2_cmd_vel.py --logdir runs/go2_flat --build-dir build \
    --reward-preset isaac_flat --speed 0.5            # tiled video + tracking error
tensorboard --logdir runs/

Flags: --reward-preset {relaxed,isaac_flat}, stairs terrain by default (drop --flat), --use-sensors, --no-self-collision --max-condim 3, --cpu for MuJoCo C. Simplifications vs Isaac Lab: blind policy (no height scan), one physical model for all envs, no terrain curriculum.

4 · Cameras for every env

cam = native.create_camera(sim, 128, 128)
cam.render()
rgb, depth = cam.rgb(), cam.depth()                   # (envs, cams, H, W, 3) uint8 / (envs, cams, H, W) float32 [m]

from mjmlx_camera_cuda import CudaCamera              # Linux + NVIDIA + CUDA torch: zero-copy
g = CudaCamera.try_create(cam)                         # None elsewhere -> keep the readback above
cam.render(); rgba, depth = g.read()                   # CUDA tensors

5 · C / C++ (or anything with FFI)

#include <mjmlx/mjb.h>
MjbBackend* gpu = mjb_create_backend(MJB_BACKEND_MLX);   // GPU engine; MJB_BACKEND_CPU = MuJoCo C
MjbModel* m = mjb_load_model(gpu, "humanoid.xml");
MjbBatchedConfig cfg = { .num_envs = 8192 };
MjbBatchedSim* sim = mjb_batched_create(m, &cfg);
mjb_batched_step(sim, controls);

6 · Verify and benchmark

just check-ci                     # CPU-vs-GPU trajectory tests (runs on lavapipe, no GPU needed)
cd build && ctest -L robust       # batch sanity sweep over nv x constraint types
uv run python scripts/bench_go2_step.py --build-dir build --envs 4096
uv run python scripts/examples/go2/compare_cpu_gpu_go2.py --build-dir build   # 1-step error vs MuJoCo C
just check-video-export           # CPU | GPU side-by-side video

What is and isn't supported

Supported (checked against MuJoCo C)

free / ball / hinge / slide joints; Euler integration; pyramidal friction (condim 3/4/6); plane / sphere / capsule / box / cylinder / ellipsoid / mesh (GJK/EPA) and SDF contacts; joint limits; friction loss; fixed and spatial tendons; gravity compensation; TENDON / SITE transmission; 19 sensor types; RGB + depth cameras.

Not supported (yet)

Equality constraints, actuator activation dynamics (FILTER / INTEGRATOR / MUSCLE), RK4, heightfield contacts (cameras do render hfields), islands / noslip / sleep, per-env physical models, differentiable physics.

Good to know

Constraint rows are capped at 72 per env on the shared-memory solver path (contacts beyond that are dropped; Go2 is fine). Long contact-rich rollouts diverge from MuJoCo chaotically, so accuracy is judged per control step (Go2: 3.6e-5 rad mean).

Full matrix: CONFORMANCE.md. Design notes: ARCHITECTURE.md.
